# 제품 지표 기능 명세

## 공통 기준

- 날짜 경계는 모두 `Asia/Seoul`을 사용한다.
- **실사용자**는 조회 시점에 `users.deleted_at IS NULL AND users.is_bot = FALSE`인 계정이다. 동거 봇과 탈퇴 계정은 모든 분자·분모에서 제외한다.
- 일별 인증 활동과 루틴 수행 행동은 서로 다른 원천으로 측정한다.
- 현재 `house_members`는 재가입 시 같은 행의 상태와 `joined_at`을 갱신하므로 개인/공동 분류는 과거 상태가 아닌 **조회 시점의 현재 세그먼트**다.

## 일별 인증 활동

- 유효한 사용자 JWT로 user-api를 요청하면 HTTP 결과와 무관하게 그 요청을 인증 활동으로 본다.
- `user_daily_activity`에 사용자·KST 날짜당 한 행만 저장한다.
- 앱 인스턴스의 날짜별 사용자 캐시는 같은 날 반복 요청의 DB 접근을 줄이는 최적화일 뿐 정합성 근거가 아니다. unique `(user_id, activity_date)`가 다중 인스턴스와 동시 요청의 최종 방어선이다.
- 기록은 사용자 기능의 비즈니스 트랜잭션과 분리한 짧은 트랜잭션에서 best-effort로 수행한다. 관측 저장 실패가 원래 API 응답을 실패시켜서는 안 된다.

## D1/D7/D30 Retention

- 코호트 날짜는 `users.created_at`이 속한 KST 가입일이다.
- Dn 재방문은 가입일로부터 정확히 n일째의 `user_daily_activity` 존재 여부다. `D7`은 가입 후 1~7일 누적 방문이 아니다.
- 아직 n일이 지나지 않은 미성숙 코호트의 Dn은 집계 대상이 아니며 API에서 `null`로 표시한다.
- 비율은 `해당 날짜 활동 사용자 수 / 해당 가입일 실사용자 수 × 100`이다.

## 북극성 지표

- 관측창은 조회일을 포함한 최근 7개 KST 날짜다.
- `routine_logs.status = COMPLETED`이고 `completed_at`이 관측창에 속한 로그를 사용한다.
- 한 사용자가 실제 완료한 `completed_at`의 서로 다른 KST 날짜가 3일 이상이면 달성 사용자다.
- 비율은 `달성 사용자 수 / 전체 실사용자 수 × 100`이다.

## 행동 지표

- **루틴 완료율** 관측창은 오늘을 제외한 종료된 최근 30개 KST 날짜다. 오늘은 day-end `FAILED`가 확정되지 않아 제외하며, `COMPLETED / (COMPLETED + FAILED) × 100`으로 계산한다. `PENDING`은 사용하지 않는다.
- **평균 스트릭**은 전체 세그먼트 사용자를 분모로 하며 스트릭 행이 없거나 `last_success_date < 조회일 - 1일`이면 0으로 본다.
- **재시작** 관측창은 조회일을 포함한 최근 30개 KST 날짜다. `completed_at`의 서로 다른 KST 완료일 사이에 완료 없는 날짜가 3일 이상 있고 그 뒤 다시 완료한 경우다.
- **재시작 대상 사용자**는 관측창에서 한 번 이상 완료한 뒤 종료된 KST 날짜만으로 3일 이상 완료 공백을 경험한 사용자다. 다시 완료한 사용자와 관측창 종료까지 돌아오지 않은 사용자를 모두 포함하되, 아직 끝나지 않은 조회일은 미복귀 공백 일수에 넣지 않는다.
- **재시작률**은 `재시작 사용자 수 / 재시작 대상 사용자 수 × 100`이다.

## 개인군과 공동 참여군

- **공동 참여군(`SHARED`)**은 현재 ACTIVE 멤버십으로 미삭제 집에 속하며 같은 집에 본인 외 ACTIVE 실사용자가 한 명 이상 있는 사용자다.
- 비공개 기본 집에 본인과 동거 봇만 있거나 실제 동료가 없는 사용자는 **개인군(`PERSONAL`)**이다.
- 전체(`OVERALL`)·개인군·공동 참여군별 사용자 수, 완료 수/대상 수, 완료율, 평균 스트릭, 재시작 대상/재시작 수와 재시작률을 함께 제공한다.

## 데이터 한계

- 배포 전 일별 인증 활동은 소급 복원하지 않는다.
- 루틴 기록 PURGE나 회원 데이터 파기 정책으로 원천 로그가 삭제되면 과거 집계가 달라질 수 있다. 장기 고정 추이가 필요하면 비식별 일별 스냅샷을 별도 설계한다.
- 현재 멤버십만으로 과거 날짜의 공동 참여 여부를 복원하지 않는다.
