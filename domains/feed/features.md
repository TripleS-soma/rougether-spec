# 공개 SNS 피드

사용자 확정 방향: 일상 사진·글과 루틴 인증·꾸민 방 공유를 모두 허용하고, 전체 공개 피드부터 제공한다. 팔로우는 후속이다. 이 문서는 첫 서버 구현 계약이며 프론트 구현·운영 배포 완료를 의미하지 않는다.

## 첫 버전

| 기능 | 범위 |
| --- | --- |
| 게시물 | 사진 1–10장 + 선택 본문(최대 2,000자), 상세 조회, 본인 본문 수정·삭제 |
| 피드 | 전체/작성자별 최신 등록 ID 내림차순, 커서 목록, 새로고침 |
| 좋아요 | 등록·취소, 개수, 내가 눌렀는지 여부. 사용자·게시물당 1개 |
| 댓글 | 한 단계 댓글 작성·오래된 순 목록·본인 삭제, 최대 500자, 개수 |
| 사진 | JPEG/PNG 한 장씩 업로드, 원본당 10MiB 이하, 업로드 후 24시간 내 게시 |

글만 쓰기, 게시 후 사진 교체·순서 변경, 댓글 수정·대댓글, 팔로우·팔로잉 피드, 반응 푸시, 추천 순위·동영상·스토리·DM·해시태그 검색은 이번 범위에 포함하지 않는다. 신고·차단·운영자 숨김의 출시 범위는 [열린 질문](../../open-questions.md#sns-공개-피드)에서 결정한다.

## 공개 범위와 기존 기능

- 공개 대상은 인증된 활성 일반 회원이다. 비로그인 공개 링크와 봇 계정의 피드 접근은 지원하지 않는다.
- 작성자 정보는 `userId`, `nickname`, `profileImageKey`만 제공한다. 이메일·집 초대코드·개인 루틴 목록은 포함하지 않는다.
- 루틴 인증·꾸민 방은 사용자가 공유를 선택한 이미지와 본문으로 표현한다. 기존 인증사진·방 상태를 자동 게시하지 않는다.
- 실제 완료 기록과의 연결·검증 배지·루틴 가져오기·방 방문은 기존 도메인의 별도 계약이 필요하다. 피드 공유로 원래 API의 권한은 확대되지 않는다.
- 게시·좋아요·댓글에 재화 보상을 지급하지 않는다.
- 본문·댓글은 앞뒤 공백을 제거하고 원문으로 저장한다. 자동 번역하지 않으며 기존 금칙어 검사를 적용한다. 길이는 UTF-16 기준(일부 이모지는 2자)이다. 앱 안내는 안정적인 오류 `code`로 현지화한다.

## 사진과 삭제

- 사진 원본은 디코딩·회전 보정 후 최대 긴 변 1,600px의 JPEG로 다시 저장한다. EXIF·위치·기타 metadata는 제거한다. 원본 가로/세로 각각 8,192px, 전체 3,200만 화소를 넘으면 거부한다.
- 저장된 사진은 비공개 `storageKey`와 치수로 식별한다. **CDN base URL과 조합하지 않고 인증된 이미지 조회 API로 표시한다.** 프로필 이미지 key의 기존 CDN 계약은 유지한다.
- 게시 전에는 업로더만 미리보기·취소할 수 있다. 미사용 이미지가 30개면 추가 업로드를 제한한다.
- 타인의 이미지, 미완료·만료·이미 게시된 이미지, 중복 imageId는 게시물에 연결할 수 없다.
- 게시물 삭제 후 새 목록·상세·반응·이미지 요청은 즉시 차단한다. 본문·반응을 제거하고 사진은 비동기 정리한다. 이미 받은 화면/파일을 원격으로 회수할 수는 없으므로 프론트도 삭제 후 캐시를 비운다.
- 댓글 삭제는 본문을 비우고 목록·개수에서 제외한다. 삭제 안내용 빈 댓글은 표시하지 않는다.
- 회원탈퇴 후 해당 회원의 글·댓글·좋아요는 새 조회와 개수에서 즉시 제외하고 잔여 토큰의 접근을 거부한다. 피드 본문·댓글 내용·좋아요·사진은 후속 정리한다. 기존 루틴 인증 기록 보존 정책과는 별개다.
- 정상 운영 시 정리 작업은 실행 완료 후 5분 간격으로 반복한다. S3 실패는 재시도하므로 실제 파기 시각의 상한을 보장하지 않는다. 미완료 업로드는 전송과 충돌하지 않도록 24시간 만료 이후 정리한다.
- 게시물/댓글 ID·작성자 ID·요청 UUID·해시는 재시도 방지용 삭제 기록으로 남을 수 있다. 사진 S3 객체는 버전과 삭제 marker까지 제거한다.

## 재시도와 목록

- 게시물·댓글 등록은 클라이언트가 생성한 UUID로 재시도를 식별한다. 같은 UUID와 같은 정규화 본문/사진 순서는 원래 결과를 돌려준다. 다른 내용 또는 삭제된 결과의 재사용은 409다.
- 본문을 수정한 글에 원래 등록 요청을 재전송해도 본문을 되돌리지 않고 현재 글을 반환한다.
- 좋아요 등록·취소와 본인 게시물·댓글 삭제는 반복 호출해도 중복 변경하지 않는다. 다만 부모 게시물이 없어지면 댓글·반응 경로는 404다.
- 게시물은 `id < cursor`, 댓글은 `id > cursor`로 이어진다. `nextCursor=null`이면 현재 다음 페이지가 없다. 새로고침은 cursor 없이 요청한다.

프론트 연결 순서와 요청/응답 예시는 [API 계약](api.md)을 따른다.
