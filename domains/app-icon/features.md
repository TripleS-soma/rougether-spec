# 고양이 앱 아이콘 기능 명세

## 상태 판정

우선순위는 `STREAK_CHAMPION` → `DAILY_SUCCESS` → 미접속 단계 → `NORMAL`이다.

| state | 조건 | 기본 문구 |
| --- | --- | --- |
| `NORMAL` | 아래 조건에 해당하지 않음 | 왔냥? 기다리고 있었다냥! |
| `MISSING_YOU` | 실제 마지막 foreground 활동 후 48시간 이상, 96시간 미만 | 요즘 좀 뜸하다냥… |
| `TEARY` | 96시간 이상, 168시간 미만 | 보고 싶다냥… |
| `SOBBING` | 168시간 이상 | 언제 돌아오냥… 기다리고 있다냥. |
| `DAILY_SUCCESS` | 오늘의 루틴 완료 로그 또는 오늘 실제 완료한 투두가 1개 이상 | 오늘도 해냈다냥! |
| `STREAK_CHAMPION` | 오늘 기준 유효 루틴 스트릭이 7일 이상 | 꾸준함의 왕이다냥! |

- 미접속은 달력 날짜가 아닌 경과 시간으로 판정한다. 하루·스트릭 기준은 `Asia/Seoul`(KST)이다.
- 루틴은 `routine_date = 오늘`, `status = COMPLETED`를 사용한다. 과거 날짜의 루틴을 오늘 소급 완료한 것만으로 오늘 성공이 되지 않는다.
- 투두는 `status = COMPLETED`이고 `completed_at`이 오늘 00:00 이상, 다음 날 00:00 미만이면 인정한다. 마감일이 없거나 지난 투두도 포함한다.
- 완료 취소는 다음 조회에 반영한다. 항목 삭제만으로 기존 완료 이력을 지우지 않는 경우 그 실천도 유지된다.
- 스트릭은 기존 `currentCountOn(오늘)` 계약을 사용한다. 마지막 성공일이 어제라면 오늘도 유효하고, 오늘을 완료하지 않은 채 다음 날이 되면 만료된다. 투두로 루틴 스트릭을 올리지 않는다.
- 앱 복귀는 미접속 상태를 해제하되 오늘 성공·왕관은 유지한다. 완료/취소 이후 모바일은 상태를 다시 조회한다.
- 활동 기록이 없는 기존 사용자에게 로그인·토큰 refresh 시각을 소급 적용하지 않는다. 이때 미접속은 기본 상태이고 성공·왕관 판정은 가능하다.

## 실제 앱 활동

앱의 실제 foreground 진입·복귀 및 사용 중 활동만 기록한다. background fetch, 푸시 수신, 토큰 refresh, 상태 조회는 이 기록을 갱신하지 않는다. 서버가 현재 시각과 JWT 주체를 사용하므로 클라이언트의 사용자 ID·접속 시각 입력은 받지 않는다.

## 미접속 알림

`APP_INACTIVITY_REMINDER` 타입을 기존 `REMINDER` 그룹에 추가한다. 아이콘 성공 상태에 별도 축하 푸시는 보내지 않는다.

| 단계 | 제목 | 본문 |
| --- | --- | --- |
| 48시간 | 고양이가 기다린다냥 | 오늘은 어떤 하루였냥? 잠깐 얼굴 보러 와주라냥. |
| 96시간 | 보고 싶다냥… | 며칠째 조용해서 조금 심심하다냥. 같이 하나만 해볼까냥? |
| 168시간 | 언제 돌아오냥… | 오랜만이어도 괜찮다냥. 네 자리는 그대로 있다냥. |

- KST 09:00 이상 21:00 미만, 30분마다 확인한다. 서버 재시작도 허용 시간 안에서 확인한다. 기준 시간 도달 즉시 발송을 보장하지 않는다.
- 실제 활동 기록이 있는 활성 일반 사용자만 대상이다. 탈퇴 사용자·봇·신규 API를 아직 사용하지 않은 기존 사용자는 제외한다.
- 한 미접속 회차에서 각 단계의 알림 내역을 최대 1건 적재한다. 오래 멈췄다가 실행하면 현재 해당하는 가장 높은 단계 1건만 만들고 이전 단계는 건너뛴다. 7일 이후 같은 회차에는 추가 알림이 없다.
- foreground 기록 시 새 회차가 시작된다. 내역과 마지막 적재 단계는 같은 트랜잭션으로 저장한다.
- 발송 직전에 복귀·오늘 성공·왕관·탈퇴·더 높은 단계의 신규 알림을 확인해 오래된 대기 알림을 `BLOCKED`로 종결한다. 발송 처리와 복귀가 동시에 도착하면 사용자 잠금으로 순서를 정한다. 이미 FCM으로 전달된 알림은 회수하지 않는다.
- `ALL` 또는 `REMINDER` 설정 off면 FCM을 호출하지 않는다. 기존 정책대로 알림함 내역은 남고 해당 단계는 소진된다. 설정을 켜도 지난 단계는 재발송하지 않는다.
- 기존 토큰 등록·멀티디바이스 발송·무효 토큰 정리 경로를 재사용한다. 토큰 없음·전체 실패는 `FAILED`, 1개 이상 발송 성공은 `SENT`이다. `FAILED` 자동 재시도는 없다.
- 발송은 기존 FCM과 같은 best-effort이다. 통상적인 동시 실행·재실행은 중복을 막지만 FCM 수락 직후 DB 커밋 전 프로세스가 종료되면 중복 가능성이 있다.

## 모바일 적용

앱 아이콘은 앱 번들의 상태별 리소스로 매핑한다. 미지원 상태·플랫폼은 기본 아이콘으로 처리한다. 서버가 이미지 다운로드·OS 교체를 수행하지 않으며, 푸시를 받았다는 이유로 foreground 기록을 보내지 않는다. 알림을 눌러 앱을 실제로 연 경우 기록한다.
