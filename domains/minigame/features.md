# 미니게임 기능 명세

## 게임 목록과 플레이

| gameCode | 이름 | 조작 | 점수 | 최대 진행 시간 |
| --- | --- | --- | --- | --- |
| `room-runner` | 루틴 러너 | 탭으로 점프해 장애물 피하기 | 진행 tick을 6으로 나눈 정수 몫 | 18,000 tick / 5분 |
| `cat-stairs` | 고양이 계단 | 다음 계단 방향에 맞춰 좌우 입력 | 맞게 오른 계단 수 | 7,200 tick / 2분 |
| `cat-merge` | 고양이 합치기 | 4×4 보드를 상하좌우로 밀어 같은 숫자 합치기 | 합쳐서 생성한 타일 값의 누적 합 | 18,000 tick / 5분 |

- 세 게임은 기존 `rulesVersion=1`과 난이도를 높인 `rulesVersion=2`를 함께 지원한다. 새 앱은 2를 명시하고, 버전을 보내지 않는 기존 앱에는 1을 제공한다. 서버와 클라이언트는 같은 게임·규칙 버전·시드·입력으로 같은 상태·점수를 재현해야 한다.
- 전체 회원 랭킹용 플레이는 서버가 발급한 해당 게임의 세션과 시드로 시작한다. 서버가 제공하지 않거나 앱이 지원하지 않는 규칙 버전은 랭킹용 플레이에 사용하지 않는다. 요청 버전과 시작 응답 버전이 다를 때 다른 규칙으로 진행하거나 점수를 제출하지 않는다.
- 연습 플레이는 서버 기록 및 랭킹에 포함하지 않는다.
- 게임 진행 시간은 60 Hz이며 일시정지 시간을 제외한다. 앱이 비활성 상태가 되면 멈추고, 복귀 후 사용자가 이어 하기를 선택한다. 서버의 제출 만료 시간은 일시정지 중에도 연장되지 않는다.
- 루틴 러너는 최초 충돌 또는 최대 tick 도달, 고양이 계단은 오답·시간 만료·최대 tick 도달 시 종료한다. 종료 전 임의 기록 저장은 허용하지 않는다.
- 고양이 합치기는 이동 불가·2,000회 유효 이동·최대 tick 도달 시 종료하며 사용자가 중간에 기록을 저장할 수 있다. 2,048 타일 생성 후에도 계속 플레이한다.

## 난이도 변경

- 루틴 러너: 규칙 2는 첫 장애물을 60 tick(기존 90 tick)에 생성하고, 이동 속도를 8에서 시작해 40초에 16까지 올린다(기존 6→12). 점프 속도는 15(기존 16)이며 장애물 너비·높이를 키우고 생성 간격을 줄인다. 최대 18,000 tick·600회 점프와 점수 `floor(ticks / 6)`은 유지한다.
- 고양이 계단: 규칙 1의 초기 제한 시간 180 tick, 정답 후 `max(45, 180 - floor(score / 5) × 6)`을 보존한다. 규칙 2는 초기 72 tick(1.2초), 정답 후 `max(18, 72 - floor(score / 3) × 4)`로 줄인다. 42계단부터 정답마다 18 tick(0.3초)을 제공한다. 계단 경로, 최소 입력 간격 6 tick, 최대 7,200 tick은 같다. 제한 시간이 끝나는 tick에는 입력을 처리하지 않는다.
- 고양이 합치기: 4×4 보드·합친 타일 값 누적 점수는 유지한다. 규칙 1은 초기 2타일·새 타일의 4 등장 확률 10%이고, 규칙 2는 초기 4타일·4 등장 확률 25%다. 규칙 2는 유효 이동 8회마다 일반 타일 생성 뒤 타일을 하나 더 생성한다. 빈칸이 없으면 추가 생성을 생략한다. 변화 없는 이동은 횟수에 포함하지 않는다.

## 기록 제출

- 세션은 생성 후 30분 동안 처음 제출할 수 있다. `expiresAt`에 도달하면 미완료 기록의 새 제출을 거부한다.
- 클라이언트는 `ticks`와 게임별 점프 또는 방향 입력만 보낸다. 서버는 저장된 세션의 시드와 규칙 버전으로 입력 범위·종료 상태·점수를 검증한다. 완료 요청으로 세션의 버전을 변경할 수 없다.
- 규칙 2 배포 전에 시작한 규칙 1 세션도 기존 30분 기한까지 완료할 수 있다. 규칙 1의 입력 제한·난수·물리·점수·제출 해시 형식은 그대로 유지한다.
- 제출한 진행 시간이 서버가 관측한 세션 경과 시간보다 2초를 초과해 앞서면 거부한다.
- 게임 시작·완료·회원탈퇴는 동일 회원의 상태 변경을 직렬화한다. 완료 기록과 개인 최고점은 같은 트랜잭션으로 반영하며, 동시 제출로 최고점이 낮아지거나 탈퇴 후 기록이 다시 생기지 않아야 한다.
- 이미 완료한 세션에 동일한 입력을 재전송하면 최초 성공 응답을 그대로 반환한다. 해당 응답의 최고점·순위는 최초 완료 당시의 값이며, 이후 다른 플레이나 다른 회원의 점수가 바뀌어도 재계산하지 않는다.
- 완료한 세션의 동일 입력 재전송은 만료 후에도 허용한다. 유효한 다른 입력을 같은 세션에 제출하면 409다. 제출 결과를 알 수 없는 경우 새 입력으로 바꾸지 않고 같은 요청을 재시도한다.

## 전체 회원 랭킹

- 랭킹은 게임·규칙 버전별 누적 개인 최고점이다. 같은 난이도를 플레이한 전체 회원을 대상으로 하며 집·친구·지역·기간별로 나누지 않는다. 새 앱의 기본 화면은 규칙 2 랭킹이고, 별도 난이도 선택 UI는 제공하지 않는다.
- 해당 게임·규칙 버전에서 완료 기록을 한 번 이상 저장한 미탈퇴 일반 회원을 포함한다. 첫 기록이 0점이어도 참가자다. 봇과 탈퇴 회원은 제외한다.
- 해당 게임·규칙 버전의 첫 기록은 `personalBest=true`다. 이후에는 같은 버전의 기존 최고점보다 클 때만 최고점·달성 시각을 갱신한다. 동점 재달성은 갱신하지 않으며 다른 버전의 기록을 덮어쓰지 않는다.
- 순위는 같은 게임·규칙 버전에서 `자신보다 높은 최고점을 가진 회원 수 + 1`이다. 동점은 공동 순위 `1, 1, 3`으로 표시한다.
- 정렬은 최고점 내림차순, 달성 시각 오름차순, 회원 ID 오름차순이다. 상위 **50명**을 반환하며, 경계에서 동점이어도 50명을 넘겨 확장하지 않는다.
- `myEntry`는 50명 밖의 본인 기록도 반환한다. 본인 완료 기록이 없으면 null이다. `totalPlayers`는 해당 게임·규칙 버전에 기록이 있는 유효 참가자 수다.
- 랭킹 응답에는 회원 ID·현재 닉네임·최고점·순위가 포함되며 로그인한 회원이 조회할 수 있다. 닉네임 변경은 다음 조회에 반영한다. 닉네임이 비어 있으면 `이름 없는 이웃`을 표시한다.
- 최고점의 구분 키는 `(gameCode, rulesVersion, userId)`다. 기존 규칙 1 최고점·달성 시각을 보존하고 규칙 2 최고점은 별도로 시작한다. 규칙 변경은 시즌 리셋이나 기존 기록 삭제가 아니다.
- 규칙 1 원본 입력을 보관하지 않으므로 과거 점수를 규칙 2로 환산하거나 재검증하지 않는다. 규칙 1의 높은 기록이 규칙 2의 최고점·순위·참가자 수에 영향을 주지 않는다.

## 데이터 보관과 탈퇴

원본 점프·방향 입력은 제출 처리에만 사용하고 DB에 저장하지 않는다. 완료 입력의 SHA-256 해시와 검증된 점수·완료 응답은 저장한다. 닉네임 사본은 저장하지 않는다.

회원탈퇴 트랜잭션에서 본인의 모든 게임·규칙 버전의 세션과 최고점을 즉시 삭제한다. 이후 랭킹에도 노출하지 않는다. 저장 구조는 [erd.md](../../erd.md)를 따른다.

## 버전 전환

목록·시작·랭킹의 선택 쿼리 `rulesVersion`은 생략하면 1이다. 새 앱은 세 요청에 모두 2를 명시하며 조회 캐시도 게임·버전별로 구분한다. 지원하지 않는 버전으로 요청하면 다른 버전으로 대신 실행하지 않고 오류를 반환한다. 완료 요청과 재전송은 발급된 세션 버전을 따른다.

버전별 저장·조회와 규칙 1·2 검증을 지원하는 서버가 먼저 배포되어야 한다. 기존 서버가 규칙 2 요청을 처리하거나 버전별 최고점 행을 잘못 읽지 않도록 서버 교체가 완료된 뒤 새 앱을 배포한다. 규칙 2 기록이 생긴 후에도 롤백 대상 서버는 두 버전의 저장·조회를 지원해야 한다.
