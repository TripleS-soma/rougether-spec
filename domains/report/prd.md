# AI 주간 회고 — PRD

상위 문서: [product.md](../../product.md) · [features.md](../../features.md) · [erd.md](../../erd.md) · [api.md](../../api.md)

## 한 줄 정의

한 주(일~토, KST)의 루틴 수행/실패 기록을 서버가 집계하고 LLM이 **구조화된 회고**(요약·잘한 점·실패 패턴·제안)로 정리해 사용자에게 돌려주는 도메인. product.md P2 "AI 고도화 — 주간 회고 생성"의 첫 구현이며, 멘토 피드백의 **루틴 실패 패턴 분석 기반 초개인화**로 가는 입구다.

## 왜 필요한가 (문제)

- 하루 단위 완료 체크만으로는 "이번 주에 무엇이 잘 됐고 무엇이 반복해서 무너지는지"가 보이지 않는다. 사용자가 스스로 캘린더를 되짚어 패턴을 찾는 일은 거의 일어나지 않는다.
- 통계 숫자만 보여주는 회고는 읽히지 않는다. 숫자를 사람이 읽는 문장으로 바꾸고, 다음 주에 시도할 만한 제안까지 붙여야 행동으로 이어진다.

## 이 도메인이 제공하는 가치

- **주간 단위 성찰 자동화**: 사용자가 아무것도 하지 않아도 매주 회고가 만들어진다(배치 생성). 사용자는 읽기만 한다.
- **실패 패턴의 언어화**: 요일별·루틴별 완료/실패 집계를 LLM이 해석해 "화·목 저녁 루틴이 반복해서 빠진다" 같은 패턴을 문장으로 짚어 준다.
- **항상 결과가 있음**: LLM 호출이 실패해도 서버 집계와 고정 문구로 회고를 남긴다(`FALLBACK`). 회고가 빈 주는 "그 주에 루틴 기록이 아예 없던 경우"뿐이다.
- **개인정보 최소 전송**: LLM에는 닉네임·소개글(`bio`)·선택 목표·루틴 집계(루틴 제목·카테고리명 포함)만 보낸다. 이메일·집·다른 사용자 정보는 넣지 않는다.

## 핵심 시나리오

1. **생성(배치)**: 매주 일요일 00:30 KST, 직전 일~토 주에 루틴 수행/실패 기록이 있는 사용자마다 집계 → LLM 회고 생성 → `weekly_reports`에 사용자·주당 1건 저장.
2. **조회(앱)**: 사용자가 회고 목록과 상세를 본다 — 조회 API는 별도 이슈(#287)에서 확정.
3. **실패 대비**: LLM 응답이 스키마를 어기거나 호출이 실패하면 1회 재요청 후 `FALLBACK`으로 저장한다(통계 + 고정 요약, 섹션은 빈 배열). 재생성은 없다.

## 경험 루프에서의 위치

```
루틴 완료/실패 기록(routine_logs)  ← 루틴/투두 도메인이 생성(day-end 배치의 FAILED 포함)
  → [이 도메인] 주간 집계 + LLM 회고 → weekly_reports
  → 사용자가 회고를 읽고 다음 주 루틴을 조정   → 루틴/투두 도메인
```

## 담당 범위

- **table**: `weekly_reports`
- **기능**: 주간 집계, LLM 회고 생성 배치, 회고 조회(예정). 상세는 [features.md](features.md) · [api.md](api.md).

## 의존성 (타 도메인)

- **루틴/투두**: 집계 원천은 `routine_logs`(`COMPLETED`/`FAILED`)와 `routines`(제목·카테고리·`origin_routine_id` 계보)·`streaks`. 주 전체를 로그 단독으로 소싱하므로 **그 주 토요일의 day-end 배치가 완료된 뒤**에만 생성한다.
- **회원**: 프롬프트 입력으로 `users.nickname`·`bio`, `user_goals`(대표 목표 표시)를 쓴다. 탈퇴(익명화) 회원은 생성 대상에서 제외하고, 탈퇴 잔여 데이터 하드 파기 시 `weekly_reports`도 함께 삭제한다(루틴 로그·스트릭·목표·닉네임/bio로 만든 파생 데이터).
- **알림**: 회고 완성 알림은 없다(후속 — `NotificationType` 추가는 알림 도메인 협의).
- **LLM 인프라**: OpenAI 호환 chat completions API. 모델은 설정값이라 코드 변경 없이 교체 가능하며, 사용한 모델 id를 `weekly_reports.model`에 남긴다.
