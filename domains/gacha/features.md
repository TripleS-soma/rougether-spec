# 뽑기 도메인 기능 명세

상위 문서: [features.md](../../features.md) · 데이터: [erd.md](../../erd.md) · API: [api.md](./api.md)

재화: **코인**(뽑기 비용 소모) / **다이아**(중복 아이템 전환·적립). 구분은 `user_wallets.currency_type`.

## 뽑기 목록 조회

신규 앱은 테마 공통 **벽지·바닥·가구 3종**을 노출한다. 기존 테마별 꾸미기·악세사리·캐릭터 머신은 구버전 앱의 호환 경로로 유지한다.

- **머신 목록**: `is_active=true`이고 운영 기간 `starts_at`~`ends_at` 안인 머신만 표시한다. 기간 경계 검사는 서버가 수행하되 기간 필드는 응답에 노출하지 않는다. (`gacha`)
  - 신규 앱은 `GET /api/v1/gacha?catalog=category`로 정식 코드에 대응하는 실제 머신을 **WALLPAPER → FLOOR → FURNITURE** 순서로 조회한다. 정상 운영 시 3개를 제공하되, 비활성·기간 밖 머신을 클라이언트가 임의로 채워 넣지 않는다.
  - `catalog` 생략 시 신규 3종을 제외한 기존 테마·악세사리·캐릭터 목록을 유지한다. 기존 머신 ID와 풀은 그대로 남아 캐시된 ID로도 직접 조회할 수 있으며, 보상 조회·뽑기에는 기존 활성·기간 검증을 적용한다.
  - 표시 필드: `name`, `category`(신규 3종 외에는 `null`), 테마(theme FK→`themes`), 비용(`cost_currency_type`·`cost_amount`), 1회 뽑기 수(`draw_count`), `active`.
  - 신규 3종과 캐릭터 뽑기는 모두 `themeId=null`일 수 있으므로 **테마 부재만으로 캐릭터 머신이라고 판정하지 않는다**. 정식 `category` 또는 정확한 머신 `code`를 사용한다.
- **머신 상세**: 단일 머신의 비용·구성을 조회한다. 상세 조회 자체는 활성·기간을 검사하지 않고, 기간 필드도 응답하지 않는다. (`gacha`)
- **보상 미리보기**: 단일 머신의 활성 풀에 등록된 방 꾸미기 아이템·캐릭터 악세사리·캐릭터를 이미지·이름·등급(있는 보상만)·사용자 보유 여부와 함께 조회한다. 아이템은 `placement_type`과 슬롯 타입을 함께 내려 클라이언트가 방 아이템과 캐릭터 착용 아이템을 구분한다. 풀 엔트리의 `weight`와 계산 확률은 공개하지 않는다. (`gacha_pool_entries`, `items`, `characters`, `user_items`, `user_characters`)

## 종류별 꾸미기 뽑기

| 상자 | `category` | 정식 `code` | 허용 아이템 |
| --- | --- | --- | --- |
| 벽지 | `WALLPAPER` | `wallpaper_gacha` | `placement_type=surface_slot`, `surface_slot_type=wallpaper` |
| 바닥 | `FLOOR` | `floor_gacha` | `placement_type=surface_slot`, `surface_slot_type=floor` |
| 가구 | `FURNITURE` | `furniture_gacha` | `placement_type=positioned`, `surface_slot_type=NULL`(러그·소품 포함) |

- 3종은 모두 `theme_id=NULL`, `cost_currency_type=COIN`, `cost_amount=25`, `draw_count=1`이다. 머신 ID는 서버 목록의 실제 `gachaId`를 사용하고, 클라이언트에서 여러 테마 머신을 합성하거나 고정 ID를 만들지 않는다.
- `character_slot_type`이 있거나 `category_code`가 `character_accessory`·`background`인 아이템은 포함하지 않는다. `placement_type=character`와 배경 surface도 포함하지 않는다. 아이템 이름이나 테마명으로 분류하지 않으며, 러그는 바닥이 아니라 positioned 가구다.
- 보상 미리보기와 실제 추첨에 **동일한 카테고리 적격성 필터**를 적용한다. 잘못 등록된 다른 종류·캐릭터·악세사리·배경은 3종 머신에서 배출하지 않는다.

코인을 소모해 머신을 돌리고 보상을 인벤토리/지갑에 추가한다.

- **뽑기 실행**: 머신 선택 → 단챠 또는 5+1회 선택 → 코인 차감 → 요청 횟수만큼 풀에서 추첨. (`gacha`, `gacha_pool_entries`)
  - 단챠는 `count=1`로 `cost_amount`를 차감하고 결과 1개를 지급한다.
  - 5+1회는 `count=6`으로 단챠 5회분(`cost_amount × 5`)을 차감하고 결과 6개를 지급한다.
  - 추첨은 활성 엔트리(`gacha_pool_entries.is_active`) 중 **보상 참조가 활성인 것만**(`ITEM`은 `items.is_active`+`themes.is_active`, `CHARACTER`는 `characters.is_active`) **rarity 티어 롤**로 뽑는다 — 일반 70% / 희귀 25% / 전설 5%로 등급을 먼저 정하고 등급 풀 안에서 균등, 빈 등급이면 전체 활성 풀 균등(fallback). `weight` 컬럼은 사용하지 않는다(잔존). `rarity`는 한글 `일반`/`희귀`/`전설` 3종, null이면 `일반` 취급.
  - 회수된 보상 배출 차단은 풀 필터가 코드에서 보장한다 — 캐릭터·아이템·테마를 admin에서 비활성화하면 풀 엔트리를 손대지 않아도 추첨·미리보기에서 즉시 빠진다. 이미 지급된 보유분은 회수하지 않는다.
  - 꾸미기 3종의 풀은 `reward_type=ITEM`(`item_id`→`items`)만 사용한다. `CHARACTER` 보상은 아래 캐릭터 전용 머신의 계약이며, `CURRENCY` 풀 엔트리는 추첨 대상에서 제외한다. 중복 보상의 재화 전환은 결과 응답에서 별도로 표시한다.
- **비용 검증·차감**: 보유 코인이 선택한 옵션의 비용(단챠 `cost_amount`, 5+1회 `cost_amount × 5`)보다 적으면 실행 불가(예외). 차감과 보상 지급은 하나의 쓰기 트랜잭션. (`user_wallets` — 의존)
- **활성 검증**: `is_active=false`이거나 운영 기간 밖이면 실행 거부(409 `GACHA_INACTIVE`). 목록·보상 미리보기·실제 추첨에 같은 운영 기간 규칙을 적용한다.

### 풀 등록 / 기존 머신 이행

- 신규 3종 머신은 먼저 **비활성 상태로 준비**한다. 신규 카탈로그 분기를 지원하는 서버로 전환을 완료하고 기존 서버가 사용자 요청을 처리하지 않음을 확인한 뒤, 배포된 버전·정상 상태·대상 머신을 검증하는 별도 절차로 활성화한다. 해당 분기를 지원하지 않는 구버전 서버로 되돌릴 때는 **먼저 신규 3종을 재비활성화**하여 기존 앱 목록에 잘못 노출되지 않도록 한다.
- 새로 생성한 활성 꾸미기 카탈로그와 명시적인 아이템 등급 변경의 풀 등록은 실제 배치 유형에 따라 위 정식 카테고리 머신으로 연결한다. 새 테마마다 꾸미기 머신을 다시 만들지 않는다. 기존 asset의 재적재는 누락된 꾸미기 풀을 자동 생성하지 않으며, 이미 비활성화한 풀 등록도 자동으로 되살리지 않는다. 캐릭터 악세사리는 기존 별도 등록 경로를 유지한다.
- 최초 통합은 기존 풀에 등록된 적격 아이템만 복사한다. 활성 풀 엔트리이면서 활성 머신의 시작 시각이 도래했고 `ends_at=NULL`인 상시 소스만 사용한다. 비활성·미시작·종료 시각이 있는 한정 머신의 보상과 뽑기에 등록되지 않은 상점 전용 아이템은 새로 편입하지 않는다.
- 기존 등록의 아이템·테마가 비활성이라도 등록 연결은 보존하되, 실제 미리보기·추첨에서는 활성 필터로 제외한다. 재활성화 시 보상도 다시 대상이 된다.
- 동일 아이템은 통합 풀에 한 번만 등록한다. 복사할 소스 등록의 등급이 충돌하면 `전설 > 희귀 > 일반` 순으로 보존하고, 지원 등급이 없으면 일반로 정규화한다. 이미 존재하는 정식 카테고리 풀 등록은 덮어쓰지 않는다. 기존 머신·풀·보유 이력은 삭제하지 않으며 구머신 종료 시점은 별도 결정한다.

## 캐릭터 악세사리 뽑기

캐릭터에 착용하는 악세사리는 상점에서 직접 구매하지 않고 아이템 뽑기로 획득한다.

- **분류·등록**: `items.placement_type = character`인 아이템을 캐릭터 악세사리로 판정한다. 활성 악세사리는 카탈로그 적재 시 같은 테마의 **악세사리 전용 머신**에 `reward_type = ITEM`으로 자동 등록한다. 전용 머신이 없으면 가구 뽑기와 같은 기본값(`COIN` 25, `draw_count = 1`)으로 만든다. 등급 가구와 악세사리를 한 풀에 섞지 않는다.
- **구매 불가**: `purchase_currency_type`과 `price_amount`는 모두 `NULL`로 저장한다.
- **균등 추첨**: 악세사리에는 등급을 두지 않는다. 해당 전용 풀의 모든 활성 엔트리는 `rarity = NULL`, `weight = 1`이며 풀 전체에서 동일 확률로 추첨한다.
- **중복 처리**: 다른 `ITEM` 보상과 동일하게 `user_items` 보유 여부로 중복을 판정하고, 이미 보유했다면 아이템 대신 **다이아 3**을 지급한다.

## 캐릭터 뽑기

온보딩 기본 캐릭터 외 나머지 캐릭터를 획득하는 전용 머신이다. 신규 꾸미기 3종 목록에는 포함하지 않으며, 기존 캐릭터 직접 조회·뽑기와 온보딩 흐름을 유지한다.

- **전용 머신**: 캐릭터 뽑기는 **테마 무관 머신 1개**로 운영한다(`gacha.theme_id`는 NULL). 풀 엔트리는 모두 `reward_type = CHARACTER`이며 `character_id`→`characters`를 가리킨다. (`gacha`, `gacha_pool_entries`)
- **비용**: **코인 500**(`cost_currency_type = COIN`, `cost_amount = 500`). 보유 코인이 부족하면 실행 거부. 꾸미기 뽑기 단가 25와 의도적으로 격차를 두어 캐릭터를 희소 보상으로 남긴다.
- **추첨**: 캐릭터 **8개 전체를 균등 추첨**한다 — 캐릭터 엔트리는 rarity를 전부 null로 두는 데이터 전제로 동일 확률이 성립한다(api.md 참고). 온보딩 기본 캐릭터도 풀에 포함된다.
- **중복 시 코인 환급**: 이미 보유한 캐릭터(`user_characters` 보유)가 나오면 지급 대신 **코인 100을 환급**한다. 신규 캐릭터는 `user_characters`로 지급하고 `acquired_at`을 기록한다. (`user_characters`, `user_wallets` — 의존)
  - 보유 판정·지급은 다른 획득 경로(온보딩 스타터 선택, 착용 교체)와 동일한 유저 행 비관적 락으로 직렬화한다 — 동시 실행이 같은 캐릭터를 중복 보유시키거나 환급 판정을 우회할 수 없다.
  - 캐릭터 중복 환급은 **다이아가 아니라 코인**으로 돌려준다(아이템 뽑기의 다이아 전환과 다름).

## 뽑기 결과 확인

획득 결과를 표시하고 중복 아이템을 전환한다.

- **결과 표시**: 이번 실행으로 획득한 아이템/다이아 목록. 방 꾸미기 아이템과 캐릭터 악세사리는 모두 `reward_type=ITEM`으로 지급하며, 아이템은 `items.asset_key`, 이름·`rarity`(악세사리는 `NULL`)를 표시한다. (`gacha_pool_entries`, `items`)
- **아이템 지급**: 미보유 아이템은 `user_items`로 인벤토리에 추가. (`user_items` — 의존)
- **중복 → 다이아 전환**: 사용자가 **이미 보유한 아이템**(`user_items` 보유)이 나오면 아이템 대신 다이아로 전환해 지갑에 적립. (`gacha_pool_entries`, `user_items`, `user_wallets` — 의존)
  - 전환값: 방 꾸미기 아이템과 캐릭터 악세사리 모두 **다이아 3**.

### 공통 결과 연출

- 서버가 확정한 결과를 입력으로 사용한다. 연출 재생·건너뛰기·결과 확인은 추가 뽑기 요청이나 보상 지급을 발생시키지 않는다. 요청 중 중복 실행을 막으며, 실패한 뽑기를 자동 재요청하지 않는다.
- 아이템별 영상을 만들지 않고, 등급별 공통 배경 영상 위에 해당 아이템의 투명 배경 `assetKey` 이미지를 합성한다. 벽지·바닥·가구 모두 같은 결과 파이프라인을 사용한다.
- 단챠 영상 길이는 일반 2.4초·희귀 2.7초·전설 2.9초이며, 높은 등급은 빛·카메라 움직임·등장 타이밍·진동을 달리한다. 네트워크 대기 시간은 영상 길이에 포함하지 않는다.
- 5+1회 응답이 정확히 6개이면 서버 결과 순서대로 여섯 번의 짧은 차임 효과음에 맞춰 각 보상 아트를 투명 배경으로 등장시킨 뒤, 전체 결과 카드를 앞면으로 보여준다. 각 보상의 등급에 따라 빛·등장 모션·진동을 강조하며, 결과 카드를 다시 한 장씩 뒤집도록 요구하지 않는다. 결과가 있지만 개수가 6개와 다르면 여섯 번의 연출을 생략하고 실제로 받은 결과 카드만 즉시 보여준다. 결과가 비었거나 요청이 실패하면 기존 실패 처리를 유지한다. 결과를 임의로 추가·삭제·재정렬하지 않으며, 중복 전환도 한 결과로 유지하고 응답의 환급 통화·수량을 그대로 표시한다. 기존 단일 뽑기 요청·차감·지급·환급 계약은 바꾸지 않는다.
- 짧은 배경음·효과음은 사용자의 효과음 설정을 따르고, 지원 기기에서 진동을 함께 제공한다. 모션 줄이기 설정에서는 등급별 영상·소리·진동 연출 없이 결과를 제공한다. 건너뛰기·영상 오류·앱의 백그라운드 전환도 이미 지급된 결과 확인을 막지 않는다.
- 세로 휴대폰 비율 변화와 상·하단 안전 영역을 고려한다. 배경 영상과 아이템은 같은 화면 좌표계로 맞추며, 결과 이름·확인·방 꾸미기 버튼이 잘리지 않아야 한다. 네이티브 영상 모듈을 포함한 새 앱 빌드가 필요하고, 출시 전 실물 기기에서 영상·소리·진동을 확인한다.

## 관련 table 요약

- **gacha**: 머신 정의 — `code`, `name`, `cost_currency_type`, `cost_amount`, `draw_count`, `starts_at`, `ends_at`, `is_active`, theme FK→`themes`?(신규 꾸미기 3종·캐릭터 뽑기는 NULL). 응답의 `category`는 정식 `code`에서 도출하며 별도 DB 컬럼을 추가하지 않는다.
- **gacha_pool_entries**: 머신별 보상 풀 — `gacha_id`→`gacha`, `reward_type`(`ITEM`/`CHARACTER` — `CURRENCY` 엔트리는 서버가 풀에서 제외, 미지원), `item_id`→`items`?, `character_id`→`characters`?, `currency_type`?·`reward_amount`?(잔존 컬럼, 미사용), `rarity`?(`일반`/`희귀`/`전설`), `weight`(잔존 컬럼, 추첨 미사용), `is_active`.

## 의존 도메인 (이 도메인이 다루지 않음)

- `user_wallets` 코인 차감·환급 → 재화/회원 도메인.
- `items` 정의·`user_items` 인벤토리 추가 → 상점/아이템 도메인.
- `characters` 정의·`user_characters` 보유 → 회원/온보딩 도메인. (캐릭터 뽑기는 `characters`를 보상으로 참조, `user_characters`로 지급)
- `themes` 테마 정의 → 상점/테마 도메인.
