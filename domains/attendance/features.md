# 연속 출석 이벤트 기능 명세

## 이벤트 생성

운영자는 코드·제목·시작일·종료일·코인 보상을 지정한다. 새 생성권 이벤트는 `targetDays=7`, `rewardItemId=null`이며 최종 생성권은 1회로 고정한다. 기본 30코인, 5일차 총 50코인을 사용한다. 기간은 최소 7일이고 활성 이벤트끼리 겹칠 수 없다.

기존 `rewardItemId`를 지정하는 가구 보상 이벤트도 호환성을 위해 유지한다. 그 경우 기존과 같이 활성 `positioned` 가구만 지정할 수 있다. 생성 이후 기간·목표·보상은 변경하지 않는다.

## 출석과 보상

- KST 날짜는 서버가 정한다. 어제 출석했으면 연속일 +1, 그 이전이면 1일차로 시작한다.
- 매일 코인과 `ATTENDANCE_REWARD` 재화 원장을 지급한다. 코인 지급이 0이면 원장은 만들지 않는다.
- 생성권 이벤트 7일차에는 `furniture_credit_accounts.balance`를 1 증가시키고 `furniture_credit_entries`에 `reason=ATTENDANCE_REWARD`, `reference_id=attendance:{eventId}`를 기록한다.
- 완료 출석 row에 `generation_credit_amount=1`, `reward_newly_granted=true`, `reward_processed_at`을 저장한다. `reward_user_item_id`는 null이다.
- 기존 가구 이벤트는 기존 `user_items` 지급을 유지한다. 이미 보유한 가구는 중복 지급하지 않는다.
- 오늘 중복 호출과 완료 후 호출은 멱등 성공이다. 추가 출석·코인·생성권 지급을 하지 않는다.
- **앱 자동 출석**(2026-09-11): 앱은 `오늘 출석하기` 버튼 외에, 그날(KST) 루틴 또는 할 일을 처음 완료하면 보상 연출이 끝난 뒤 출석 시트를 열고 같은 출석 API를 한 번 호출한다. 이벤트 없음·오늘 출석함·완주·과거 날짜 완료·같은 날 재완료·위젯 완료는 호출하지 않는다. 서버 계약은 위 멱등 규칙 그대로다 — [prd.md](prd.md) "운영 원칙".
- 출석·코인·원장·완료 보상은 하나의 트랜잭션이며 사용자 행 잠금과 출석 일자 unique 제약으로 중복을 방지한다. 생성권 지급 실패 시 출석과 코인도 롤백한다.

## AI 가구 만들기

- 메인 나의 방에서 `AI 가구 만들기`를 연다. 생성권이 없어도 잔액과 출석 이벤트 안내를 볼 수 있다.
- 본인 사진 1장(JPEG/PNG, 최대 10MB)을 선택하고 `생성권 1회로 만들기`로 접수한다. 업로드한 사진은 기존 AI 파이프라인이 처리한다.
- 생성권은 접수 시 예약하고 성공 시 소비한다. 업로드·생성 실패 시 예약을 해제하여 돌려준다. 같은 작업의 중복 정산은 무시한다.
- `requestId`로 접수 중복을 막는다. 응답 유실 후 재시도는 같은 사진과 같은 ID를 사용한다.
- 서버의 사용자별 진행 중 작업·일일 한도·소유권 검증을 유지한다. 앱을 닫아도 작업은 계속되며 다시 열면 최근 작업 목록을 불러온다.
- 완성 가구는 본인 `user_items`에 지급하며 `방에 배치하기`에서 최신 가구함을 불러온다.
- 새 생성의 생성권 요구 기본값은 활성이다. 결제 판매 활성 여부와 별개로 출석 생성권 지급·조회·사용이 가능하다.

## 상태 조회와 파기

오늘 유효한 이벤트가 없으면 `ATTENDANCE_EVENT_NOT_FOUND`다. `dailyRewards[].claimed`는 현재 연속 출석 기준이며, 완료 여부는 저장된 보상 처리 시각 기준이다.

탈퇴 데이터 파기 시 출석 이력은 보상 가구보다 먼저 삭제한다. 공유 이벤트와 마스터 가구는 사용자 파기 대상이 아니다. 생성 원본의 수명과 정리는 기존 생성 파이프라인 정책을 따른다.
