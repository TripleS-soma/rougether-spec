# 출석 이벤트 기능 명세

## 기존 STREAK 이벤트 생성

운영자는 코드·제목·시작일·종료일·코인 보상을 지정한다. 새 생성권 이벤트는 `targetDays=7`, `rewardItemId=null`이며 최종 생성권은 1회로 고정한다. 기본 30코인, 5일차 총 50코인을 사용한다. 기간은 최소 7일이고 같은 모드의 활성 이벤트끼리 겹칠 수 없다. STREAK와 CUMULATIVE는 병행할 수 있다.

기존 `rewardItemId`를 지정하는 가구 보상 이벤트도 호환성을 위해 유지한다. 그 경우 기존과 같이 활성 `positioned` 가구만 지정할 수 있다. 생성 이후 기간·목표·보상은 변경하지 않는다.

## 기존 STREAK 출석과 보상

- KST 날짜는 서버가 정한다. 어제 출석했으면 연속일 +1, 그 이전이면 1일차로 시작한다.
- 매일 코인과 `ATTENDANCE_REWARD` 재화 원장을 지급한다. 코인 지급이 0이면 원장은 만들지 않는다.
- 생성권 이벤트 7일차에는 `furniture_credit_accounts.balance`를 1 증가시키고 `furniture_credit_entries`에 `reason=ATTENDANCE_REWARD`, `reference_id=attendance:{eventId}`를 기록한다.
- 완료 출석 row에 `generation_credit_amount=1`, `reward_newly_granted=true`, `reward_processed_at`을 저장한다. `reward_user_item_id`는 null이다.
- 기존 가구 이벤트는 기존 `user_items` 지급을 유지한다. 이미 보유한 가구는 중복 지급하지 않는다.
- 오늘 중복 호출과 완료 후 호출은 멱등 성공이다. 추가 출석·코인·생성권 지급을 하지 않는다.
- **앱 자동 출석**(2026-09-11): 앱은 `오늘 출석하기` 버튼 외에, 그날(KST) 루틴 또는 할 일을 처음 완료하면 보상 연출이 끝난 뒤 출석 시트를 열고 같은 출석 API를 한 번 호출한다. 이벤트 없음·오늘 출석함·완주·과거 날짜 완료·같은 날 재완료·위젯 완료는 호출하지 않는다. 서버 계약은 위 멱등 규칙 그대로다 — [prd.md](prd.md) "운영 원칙".
- 출석·코인·원장·완료 보상은 하나의 트랜잭션이며 사용자 행 잠금과 출석 일자 unique 제약으로 중복을 방지한다. 생성권 지급 실패 시 출석과 코인도 롤백한다.

## 크리스마스 CUMULATIVE 출석

- 이벤트 `christmas_2026`은 2026-11-09~12-25(KST, 양 끝 포함)에 서로 다른 날짜 누적 30회다. 중간에 빠져도 진행은 유지하며 완료 후 추가 지급하지 않는다.
- 일반일 30코인, 누적 5/10/15/20/25/30회째는 **그날 총 60코인**이다. 완주 합계 1,080코인이고 일일 원금 한도/배치 가구 보너스와 별개다.
- 완료 보상 타입은 `NONE`이다. 목표 달성은 `progress_completed_at`으로 기록하고 아이템/생성권 지급 표식과 분리한다. 완주 시 트리를 주는 안은 폐기했으며 트리는 크리스마스 뽑기 10종에 포함한다. 누적 3회째에 여우를 추가 지급하며 최종 완료 보상과 분리한다(2026-11-11).
- 현재 연속일수 `currentStreak`를 바꾸지 않고 누적 화면은 `progressDays`를 쓴다. `dailyRewards[].claimed`도 누적 진행 기준이다. ID 지정 GET은 종료 후에도 본인 진행/보상 이력을 보여주고 POST는 기간 밖/플래그 OFF면 거절한다.
- 기존 STREAK legacy API, 보상과 루틴/투두 완료 후 자동 출석은 유지한다. 신규 크리스마스 출석은 metadata의 실제 이벤트 ID로 수동 체크한다.
- 선택된 선물 봉투 출석판의 30칸은 날짜가 아닌 출석 순번이다. 성공 응답 뒤 실제 지급 코인만 연출하고 닫는다. 같은 날 자동 재노출은 서버 `checkedInToday`로 막는다. 종료/30회 완료 후 자동 노출은 중단하고 직접 조회는 허용한다.
- 출석판 → 완전히 닫힘/보상 연출 완료 → 이벤트 안내 팝업 순서이며 동시에 띄우지 않는다. 안내 팝업 영구 숨김은 다음 날 출석판 자동 노출을 막지 않는다. 상세는 [크리스마스 기능 명세](../christmas/features.md)를 따른다.

## 누적 3일차 여우

3회째 30코인에 여우를 추가한다. 이미 3회 이상 달성한 계정도 이벤트가 열려 있는 동안 캐릭터만 한 번 수령한다. 재시도와 동시 요청, 기보유는 추가 캐릭터나 코인을 만들지 않는다. 기존 대표를 자동으로 바꾸지 않으며 사용자는 레벨 제한 없이 보유한 여우를 선택할 수 있다. 자세한 응답과 별도 수령은 [API](api.md#크리스마스-누적-3일차-여우-2026-11-11)를 따른다.

## AI 가구 만들기

- 메인 나의 방에서 `AI 가구 만들기`를 연다. 생성권이 없어도 잔액과 출석 이벤트 안내를 볼 수 있다.
- 본인 사진 1장(JPEG/PNG, 최대 10MB)을 선택한다. 생성권이 있으면 `생성권 1회로 만들기`, 없으면 `100코인으로 만들기`로 접수한다. 생성권과 보유 코인을 함께 표시한다. 업로드한 사진은 기존 AI 파이프라인이 처리한다.
- 생성권은 접수 시 1회를 우선 예약하고 성공 시 소비한다. 생성권이 없으면 코인 지갑에서 100코인을 차감한다. 업로드, 생성 실패나 작업 만료 시 실제 사용한 생성권 또는 코인을 한 번만 돌려준다. 결제 수단과 차감액을 작업별로 저장하므로 접수 후 잔액이 달라져도 환급 수단은 바뀌지 않는다.
- 생성권과 100코인이 모두 없으면 접수를 거절한다. 코인 차감, 지갑 원장, 작업과 예약은 같은 트랜잭션에서 처리한다. 내부 재시도와 완성 가구 피드백은 추가 차감하지 않는다.
- `requestId`로 접수 중복을 막는다. 응답 유실 후 재시도는 같은 사진과 같은 ID를 사용한다.
- 서버의 사용자별 진행 중 작업 제한과 소유권 검증을 유지한다. 앱을 닫아도 작업은 계속되며 다시 열면 최근 작업 목록을 불러온다.
- 완성 가구는 본인 `user_items`에 지급하며 `방에 배치하기`에서 최신 가구함을 불러온다.
- 새 생성의 생성권 요구 기본값은 활성이다. 결제 판매 활성 여부와 별개로 출석 생성권 지급·조회·사용이 가능하다.

## 상태 조회와 파기

legacy 조회는 오늘 유효한 STREAK가 없으면 `ATTENDANCE_EVENT_NOT_FOUND`다. ID 지정 조회는 종료 후에도 허용한다. `dailyRewards[].claimed`는 STREAK의 현재 연속 진행 또는 CUMULATIVE의 누적 진행 기준이다. 완료 여부는 STREAK의 보상 처리 시각 또는 코인 전용 누적의 `progress_completed_at`으로 판단한다.

탈퇴 데이터 파기 시 출석 이력은 보상 가구보다 먼저 삭제한다. 공유 이벤트와 마스터 가구는 사용자 파기 대상이 아니다. 생성 원본의 수명과 정리는 기존 생성 파이프라인 정책을 따른다.
